## 1. Executive Summary & Theological Philosophy

Phase 0.19 introduces the **Memories / My Journey System** to KOINONIA, fulfilling the core founding promise:
> *"A virtual world that grows when you grow in real life."*

### The Spiritual Journey Loop
```
Real-World Action (Calling / Event / Fitness)
       │
       ▼
Virtual Achievement (Quest Completed / PB / Attendance)
       │
       ▼
Remembered Experience (Canonical Memory Entry in Timeline)
       │
       ▼
Personal Reflection (🔒 Private Devotional Thought / Gratitude)
```

### Recognition & Reflection ONLY (Anti-Gamification Safeguards)
1. **Zero Holiness Score:** No spiritual rank, piety ladder, or holiness rating.
2. **Zero Currency for Memories:** Memory creation awards **0 LP, 0 Character XP, 0 Growth XP**.
3. **Zero Punishment:** No streaks, guilt mechanics, or expired memories.
4. **100% Private Reflections:** Reflections are strictly tagged `🔒 Private to you`. They are stored locally on the user's device and never uploaded to public walls or leaderboards.
5. **Strict Baseline Integrity:** A clean QA state contains strictly **0 memories**. Demo data is quarantined with `isDemo: true` and visibly badged with `DEMO MEMORY`.

## 2. Canonical Memory Architecture & Data Schema

The dedicated memory engine is located in `prototype/koinonia-phase19/data/memories.js`. Each memory follows a strict 15-field canonical schema:

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | String | Unique deterministic or UUID-like identifier (`mem_<timestamp>_<counter>`) |
| `communityId` | String | Fixed to `'fog'` (Fire of God Ministries) |
| `memoryType` | String | Canonical type enum (`QUEST_COMPLETED`, `EVENT_ATTENDED`, `PERSONAL_BEST`, `PLACE_DISCOVERED`, `MILESTONE_UNLOCKED`, `REFLECTION`) |
| `sourceType` | String | System source enum (`QUEST`, `EVENT`, `FIT_QUEST`, `PLACE`, `MILESTONE`, `MANUAL_REFLECTION`) |
| `sourceId` | String | Originating identifier (`Q-001`, `alpha_s01_20260912`, `FQ-V001`, `sports_hub`, etc.) |
| `title` | String | Human-readable title of the remembered moment |
| `subtitle` | String | Descriptive subtitle or milestone condition |
| `description` | String | Fuller contextual explanation |
| `placeId` | String | In-world place reference (`home`, `fog_center`, `sports_hub`, `school`, `outreach_site`) |
| `occurredAt` | String | ISO 8601 timestamp in Manila time (`UTC+08:00`) |
| `createdAt` | String | ISO 8601 creation timestamp in Manila time (`UTC+08:00`) |
| `icon` | String | Visual icon emoji representing the experience |
| `tags` | Array | Categorical tags (`['calling', 'stewardship']`, `['event', 'alpha']`) |
| `privacy` | String | Privacy level, defaulted to `'PRIVATE'` (`🔒 Private to you`) |
| `reflectionText` | String \| null | Private reflection written by the user (`null` if unwritten) |
| `metadata` | Object | Auxiliary context (e.g., `{ isPersonalBest: true, scoreDisplay: '7/10 makes' }`) |
| `isDemo` | Boolean | `true` if generated by demo seeder, `false` for authentic player history |

## 3. Deterministic Deduplication Engine

To prevent memory flooding and duplicate cards in the timeline, `memories.js` implements deterministic rules:

| Category | Uniqueness Key | Deduplication Rule |
| :--- | :--- | :--- |
| **Quests** | `sourceId` (Quest ID) | Exactly 1 memory created upon completion. Repeat submissions blocked. |
| **Events** | `sourceId` (Event Instance ID) | Exactly 1 memory created upon attendance confirmation. Duplicate blocked. |
| **Places** | `placeId` | Exactly 1 `PLACE_DISCOVERED` memory created on first visit. Revisits increment visit counter only. |
| **Milestones** | `sourceId` (Milestone ID) | Exactly 1 memory created on unlock. Quiet initialization bypasses memory generation. |
| **Personal Bests** | `sourceId` + `newScore` | **Only strictly improved scores create a new memory.** Repeat or worse scores return `{ added: false }`. |

## 10. Physical Acceptance Blocker #1: My Journey Tab Navigation & Mobile Overlay Fix

### Physical Failure Observed on Real Phone
During mobile testing on a physical smartphone (`http://192.168.2.163:18102/`), the Product Owner confirmed:
- Journey Test Lab seeding works cleanly.
- My Journey sheet opens reliably.
- `TIMELINE` tab displays memories properly.
- Steward of the Garden detail, private reflection entry, saving, and persistence work with 100% fidelity.

However, a critical blocker occurred when navigating between tabs:
1. When switching from `TIMELINE` to either `MEMORIES` or `PLACES`, the cards rendered by that tab moved/scrolled upward, visually covering and displacing the top tab navigation bar (`TIMELINE | MEMORIES | PLACES | GROWTH`).
2. The tab bar became completely invisible and untappable.
3. Subview modals (`Place History` and `Memory Detail`) lacked top-level back/close controls, leaving the user trapped with no way to navigate back.

### Root Cause Analysis
1. **Whole-Sheet Scrolling on `.bottom-sheet`:** The `.bottom-sheet` element in `#journey-modal` had an inline style `overflow-y: auto;`. Consequently, when the combined vertical height of content (5 place cards + summaries) exceeded the 90vh viewport threshold, the entire sheet container scrolled. The drag handle, sheet header, stats summary, and navigation tabs were pushed upward off the screen.
2. **Missing 3-Region Layout Separation:** The modal lacked independent vertical regions. The tabs were not isolated in an unscrollable, sticky container above the content.
3. **No Scroll Position Reset:** When switching between tabs, the container scroll offset was not reset to 0, inheriting previous scroll positions.
4. **Subviews Lacked Fixed Top Back Controls:** `#place-history-modal` and `#memory-detail-modal` placed "BACK" buttons at the very bottom of the card lists below the fold, while also inheriting whole-sheet scroll behavior.

### Architectural Resolution: 3-Region Layout & Contained Scrolling
1. **Region A — Fixed Header Area (`.journey-header-area`):**
   - Contains sheet drag handle, `MY JOURNEY` title, subtitle, and `btn-close-journey`.
   - Compact stats summary grid (`j-stat-quests`, `j-stat-events`, `j-stat-fitquests`, `j-stat-pbs`, `j-stat-sports`, `j-stat-places`, `j-stat-memories`).
   - CSS: `flex-shrink: 0; background: var(--surface-card); z-index: 25;`.
2. **Region B — Always-Accessible Sticky Tab Bar (`#journey-tab-bar.journey-tabs-bar`):**
   - Positioned as a direct sibling between Region A and Region C.
   - CSS: `flex-shrink: 0; position: sticky; top: 0; z-index: 30; background: var(--surface-card); display: flex; gap: 4px; padding: 4px 16px 8px 16px; border-bottom: 2px solid var(--border-light); overflow-x: auto;`.
   - Buttons styled with `flex: 1; min-width: 68px; text-align: center; white-space: nowrap;`.
   - Guaranteed never to scroll out of view or be covered by cards.
3. **Region C — Independent Scrollable Content Area (`#journey-content-area.journey-content-area.sheet-body`):**
   - CSS: `flex: 1 1 auto; min-height: 0; overflow-y: auto; -webkit-overflow-scrolling: touch; padding: 12px 16px 24px 16px;`.
   - Contains only the active tab's view (`journey-view-timeline`, `journey-view-memories`, `journey-view-places`, `journey-view-growth`).
   - Filter chips and place cards scroll exclusively within Region C, passing underneath Region B.
4. **Scroll Reset on Tab Switch:**
   - In `switchJourneyTab(tabName)`: `contentArea.scrollTop = 0;` is executed on every tab change.
5. **Prominent Top Back/Close Controls on Subviews:**
   - `#place-history-modal`: Added `#btn-top-back-places` (`← BACK TO PLACES`) and `#btn-close-place-history` (`✕`) in fixed header.
   - `#memory-detail-modal`: Added `#btn-top-back-journey` (`← BACK`) and `#btn-close-mem-detail` (`✕`) in fixed header.
   - Body containers styled with `.journey-subview-body` (`overflow-y: auto; flex: 1 1 auto; min-height: 0;`).
6. **Mobile Viewport Verification:**
   - Validated across iPhone SE (375x667), iPhone 12/13/14 (390x844), and iPhone XR/11 (414x896).
   - 30 new assertions added in Section 15 of `prototype/koinonia-phase19/test_phase19_suite.js` (Tests 176–205), all passing 100%.

## 11. Physical Acceptance Blocker #2: My Journey Tab Content Stacking / Exclusive View Fix

### Physical Failure Observed on Real Phone
Following the resolution of Blocker #1 (sticky tabs), the Product Owner tested Phase 0.19 on a physical smartphone and observed:
1. **Tabs are accessible:** Top tabs (`TIMELINE | MEMORIES | PLACES | GROWTH`) remain pinned at the top and fully tappable.
2. **Content stacking bug:** Tab contents were accumulating/stacking vertically instead of displaying exclusively:
   - **TIMELINE selected:** Timeline cards rendered, but immediately below them, the MEMORIES filter chips (`ALL`, `QUESTS`, `EVENTS`, etc.) and memories cards were also displayed simultaneously.
   - **MEMORIES selected:** Timeline cards remained stacked above, with Memories cards below.
   - **PLACES selected:** Timeline cards + Memories cards remained stacked above, with Place cards appended below.
   - **GROWTH selected:** Timeline + Memories + Places remained stacked above, with Growth virtues appended below.

### Root Cause Analysis: Why Inactive Views Remained Visible
1. **Missing CSS Visibility Rules:**
   - In `prototype/koinonia-phase19/styles.css` (line 1030), only `.modal-backdrop.hidden { display: none !important; }` was defined.
   - There was **no general `.hidden { display: none !important; }` rule**, and **no `.journey-tab-view` visibility rule**.
   - HTML `<div>` elements default to `display: block` in browser stylesheets. Consequently, adding or removing the CSS class `hidden` had no effect on computed layout; all 4 tab view containers remained `display: block` simultaneously.
2. **Missing JavaScript Style Display Enforcement:**
   - In `prototype/koinonia-phase19/game.js`, `switchJourneyTab()` previously only toggled `classList.add('hidden')` and `classList.remove('hidden')`.
   - It did not set `style.display = 'none'` or `style.display = 'block'`, nor did it manipulate the HTML `hidden` property.
3. **Container-Level Content Leakage:**
   - Because all four containers (`#journey-view-timeline`, `#journey-view-memories`, `#journey-view-places`, `#journey-view-growth`) occupied the DOM inside `#journey-content-area` with `display: block`, their contents rendered in vertical document order, creating the appearance of content accumulation.

### Data Verification: UI-Only Stacking vs Data Duplication
- **Underlying Data Integrity Confirmed:** The underlying player save state (`state.memories`) and runtime memory catalog were inspected.
- **Zero Data Duplication:** Every memory has a unique ID, deterministic deduplication is working properly, and `new Set(state.memories.map(m => m.id)).size === state.memories.length`.
- **Conclusion:** The visual repetition of cards was **strictly a UI/CSS display accumulation defect**, NOT duplicate records in the database or save state.

### Multi-Layered Exclusivity Architecture & Visibility Contract
A deterministic, defense-in-depth contract was implemented across CSS, HTML attributes, and runtime JavaScript:

1. **CSS Visibility Contract (`styles.css`):**
   ```css
   /* Global hidden utility */
   .hidden, [hidden], .modal-backdrop.hidden {
     display: none !important;
   }

   /* Journey tab view exclusivity */
   .journey-tab-view {
     display: none;
     width: 100%;
   }
   .journey-tab-view.active {
     display: block !important;
   }
   .journey-tab-view.hidden,
   .journey-tab-view[hidden] {
     display: none !important;
   }
   ```

2. **Deterministic JavaScript Switching Contract (`game.js`):**
   ```javascript
   function switchJourneyTab(tabName) {
     const tabs = ['timeline', 'memories', 'places', 'growth'];
     tabs.forEach(t => {
       const tabBtn = document.getElementById(`tab-btn-${t}`);
       const tabView = document.getElementById(`journey-view-${t}`);
       if (tabBtn) {
         tabBtn.classList.remove('active');
         tabBtn.setAttribute('aria-selected', 'false');
       }
       if (tabView) {
         tabView.classList.remove('active');
         tabView.classList.add('hidden');
         tabView.hidden = true;
         tabView.setAttribute('hidden', '');
         tabView.style.display = 'none';
       }
     });

     const activeBtn = document.getElementById(`tab-btn-${tabName}`);
     const activeView = document.getElementById(`journey-view-${tabName}`);
     if (activeBtn) {
       activeBtn.classList.add('active');
       activeBtn.setAttribute('aria-selected', 'true');
     }
     if (activeView) {
       activeView.classList.remove('hidden');
       activeView.classList.add('active');
       activeView.hidden = false;
       activeView.removeAttribute('hidden');
       activeView.style.display = 'block';
     }

     // Render ONLY the active tab view
     if (tabName === 'timeline') renderJourneyTimeline();
     else if (tabName === 'memories') renderJourneyMemories();
     else if (tabName === 'places') renderJourneyPlaces();
     else if (tabName === 'growth') renderJourneyGrowth();

     // Scroll reset
     const contentArea = document.getElementById('journey-content-area');
     if (contentArea) contentArea.scrollTop = 0;
   }
   ```

3. **HTML DOM Isolation (`index.html`):**
   - `#journey-view-timeline`: Contains strictly `#journey-timeline-list`.
   - `#journey-view-memories`: Contains strictly `#memories-filter-chips` and `#journey-memories-list`.
   - `#journey-view-places`: Contains strictly `#journey-places-list`.
   - `#journey-view-growth`: Contains strictly guidance text and `#journey-growth-list`.
   - Initial markup defaults `journey-view-timeline` to `style="display: block;"` and the remaining 3 views to `hidden style="display: none;"`.

4. **Cache Busting:**
   - Asset URLs in `index.html` bumped to `styles.css?v=0.19.2`, `data/memories.js?v=0.19.2`, and `game.js?v=0.19.2` to eliminate aggressive mobile browser caching.
